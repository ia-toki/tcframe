# Validator

The validator checks a test case input against the problem's constraints. It is the spec program itself, copied to `build/validator`, so there is nothing extra to build.

## Usage

```sh
build/validator validate < build/tc/aplusb_1_1.in
```

It reads one test case on stdin and prints:

1. The number of subtasks the input is valid for.
2. The subtask numbers, in ascending order, one per line.

Example, for an input that is valid for subtasks 1, 2 and 3:

```
3
1
2
3
```

An input valid only for subtask 3:

```
1
3
```

## Exit codes

| Code | Meaning |
| --- | --- |
| `0` | The input is valid |
| `1` | The input is invalid: it does not parse or breaks the constraints. The reason is printed to stderr. |
| `2` | The problem has several test cases per file, so this check doesn't apply. The check is skipped. |

## Automatic check

`tcframe make` runs the validator on every generated `.in` file. If one is rejected, `make` fails, so an invalid test case never reaches the judge.

## For external problems

A judge can use the validator to check test cases that weren't generated by `tcframe`. The distribution package contains it, so no extra build is needed.
